# PROJECT DEADZONE マスタービジョン v1.0

更新日: 2026-08-20  
状態: 現行プロジェクト最上位方針 / T0～T3開発基準  
対象: ゲーム性、方針、ゲームシステム、ストーリー、ワールド生成

## 0. この資料の役割

本書は「PROJECT DEADZONEは何を遊ぶMODPACKか」を固定する最上位資料である。

- 都市生成、JOB、Affix、勢力、クエストなど個別機能の判断は、本書のゲーム体験へ貢献するかで決める。
- 既存の詳細資料は削除せず、本書を上位方針として参照する。
- 現行の完成目標はT0～T3。T4以降は長期構想として凍結する。
- 実装済み、試作中、設計済みを混同しない。
- 都市生成は重要な柱だが、それ自体をゲームの目的にはしない。

## 1. 一文で表すPROJECT DEADZONE

**崩壊した現代都市圏を探索し、銃・近接・異常技術・魔法で戦い、Lootを持ち帰り、仲間と役割分担しながら勢力・拠点・物流・生活を再構築する、マルチ向けポストアポカリプス・ハクスラRPG。**

プレイヤーは選ばれた救世主ではない。均衡が崩れた地域へ現れ、誰を助け、何を奪い、どの仕組みを復旧させるかによって世界を変える新しい戦力である。

## 2. ゲームの正体

### 2.1 中核ジャンル

- ポストアポカリプス
- 現代銃器を主役にしたハクスラRPG
- 少数の超常・魔法・機械生命体を含むリアルファンタジー
- 都市探索と施設攻略
- サバイバル、生活、生産、物流
- マルチ協力と役割分担
- 勢力関係と地域変化

### 2.2 目指さないもの

- 工業MODを順番に消化するだけのKitchen Sink
- 都市を眺めるだけのワールド生成ショーケース
- 一発被弾ですべてが終わる純タルコフ型リアルシューター
- 魔法だけですべてを解決するファンタジーRPG
- HPだけが高い敵を撃ち続けるBoss戦
- 同じ素材の大量納品と低確率周回で時間を水増しする設計
- 似た機能を独自処理と複数MODで二重管理する構成

## 4. プレイヤー体験の柱

### 4.1 都市型Looter Combat

建物、路地、屋上、地下、道路、検問所を使って戦う。銃が主役だが、近接、Medic、支援、召喚、異常技術も独立したビルドとして成立させる。

### 4.2 生きて帰る遠征

出発前に目的、危険、装備、弾薬、医療、食料、移動手段を決める。遠征中は「もう一棟漁るか、持ち帰るか」を判断し、帰還によってLootが成長へ変わる。

### 4.3 戦闘以外も世界攻略になる

釣り、農業、料理、狩猟、解体、工業、修理、車両、鉄道、交易は副趣味ではない。強い食事、医療、弾薬、移動、除染、設備、経済を供給する攻略手段である。

都市・集落ごとに輸出品、需要、不足、発展度を持たせる。生活・生産で得た物資を必要な地域へ届ける行為を地域攻略として扱い、通貨、評判、JOB/Action XP、都市発展、交通・Trader・Mentor解放へ変換する。

### 4.4 マルチで役割が生まれる

全員が戦えることは維持する。ただし、得意分野を育てたプレイヤーがいると遠征効率、継戦能力、報酬、選択肢が明確に増える。

### 4.5 勢力が意思を持って動く

拠点、巡回、Convoy、救難、交易、占領、反撃がつながる。勢力は単なる色違いMOBではなく、思想、資源、敵対関係、台詞、Named、Boss、報酬を持つ。

### 4.6 世界を取り戻した手応え

施設制圧、通信復旧、道路開通、交易開始、NPC救助、地域安定化により、地図、品揃え、巡回、BGM、敵、Loot、会話が変化する。

## 5. コアループ

1. 友好拠点で情報、依頼、危険度を確認する。
2. JOB、装備、Skill、食事、車両を整え、遠征目的を選ぶ。
3. 道路、鉄道、水路、地下経路から進入ルートを決める。
4. 建物探索、施設攻略、救助、採集、勢力任務を並行して進める。
5. Loot容量、負傷、弾薬、天候、増援を見て続行か撤退か判断する。
6. 生還し、納品、交易、治療、修理、解体、クラフトを行う。
7. Class/JOB、Skill、Talent、装備、拠点、評判を更新する。
8. 世界状態とストーリーが変化し、次の地域・施設・選択肢が開く。

1回の遠征でメイン、NPC依頼、生活素材、装備Farmを複数進行できることを基本テンポとする。

## 6. ゲームシステム統合方針

### 6.1 Class / JOB / Skill / Talent

| 層 | 役割 |
|---|---|
| Class | 開始時の身体・戦闘傾向。初期能力値、Starter Kit、Talent開始地点を決める |
| JOB | 行動と役割の専門性。成長、昇格、専用支給、得意行動を決める |
| Skill | 戦い方を変えるActiveと強力なPassive。銃Skillは銃、近接Skillは近接を要求する |
| Talent | 小さな能力を積み上げ、経路とKeystoneでビルドを作る大規模常時成長 |
| Career/Action XP | 釣り、料理、医療、工作など、実際に続けた行動の熟練を示す |

基本方針はMine and Slash基盤へ寄せ、古いK画面、旧ステータス、旧Affixの二重管理を廃止する。名称、アイコン、効果はPDZ世界へ置き換える。

Classは開始時に選ぶ身体・戦闘の土台、JOBは友好都市や専門拠点のNPCから就職・転職するActiveな専門役割とする。JOBはLv到達で自動進化させず、条件を満たした候補からプレイヤーが選ぶ。未発見の上位JOBは非表示、発見済みで条件不足なら必要Lv、Action XP、Story、施設を日本語で表示する。

### 6.2 戦闘ビルド

- Firearms: ダメージ、リロード、弾薬効率、貫通、跳弾、状態弾、単体火力。
- Melee/Tank: ノックバック、ガード、感染耐性、重装、群れ制御。
- Medic/Support: 治療、蘇生、範囲支援、状態異常除去、Buddy支援。
- Scout: 機動、索敵、弱点、サプレッション、動物・機械コンパニオン。
- Engineer/Mechanic: タレット、装置、車両、修理、弾薬・設備供給。
- Anomaly Researcher: 異常エネルギー、制御された魔法、機械生命、リスク付き高出力。

魔法は世界観上「異常現象、WARDEN技術、AEGIS研究、感染共鳴」として扱う。銃職の遠距離Skillを銃なしで撃てる魔法にはしない。

### 6.3 Loot / Affix / Enchant

- Mine and Slash系ステータスとAffixを装備評価の正本にする。
- TaCZ銃、MOD防具、工具、近接を同じLoot評価へ接続する。
- レア度、装備条件、実ダメージ、Tooltipを一致させる。
- Affixは解体、素材化、再付与、Rerollへ循環させる。
- Enchantは世界観に合わせて共存させるが、同じ効果の二重計算を避ける。
- 装備は「強い数字」だけでなく、Buildを変える効果を持つ。

### 6.4 生存・医療

- 渇き、温度、負傷、感染は遠征判断を増やすために使う。
- 不快な常時ダメージや説明のない即死は採用しない。
- 部位・HP・Down・Reviveは単一の責任系へ寄せ、複数MODの致命判定を重ねない。
- Medicは他プレイヤーの治療、感染対策、蘇生で明確な価値を持つ。
- 死亡には損失を残すが、墓・回収・救援により再挑戦可能にする。

### 6.5 クエスト

| 系統 | 担当 | 内容 |
|---|---|---|
| メイン・恒久Guide | FTB Quests | ストーリー、MOD導線、長期目標、章解放 |
| NPC固有依頼 | Realm RPG Quests | 会話、人物、地域、短い連続依頼 |
| 反復契約 | Bountiful | 賞金首、納品、救助、釣り、狩猟、物流 |

ロック条件は日本語で表示し、報酬は提出物を上回る価値を持たせる。単なるバニラ素材アイコンの流用を避け、内容が分かるアイコンを使う。

### 6.6 経済と生産

- 現金だけでなく、物々交換、勢力通貨、部品、医薬、燃料を使う。
- 各勢力に得意資源と不足資源を持たせる。
- 各都市・集落にも輸出2～3カテゴリ、需要2～4カテゴリ、不足状態、発展度を持たせる。
- Bountifulを地域需要の契約、Easy NPCを物々交換、FTB/Realm RPGを復興・人物依頼へ使う。
- 在庫と需要連動価格はLightman's Currencyを第一候補としてtest Profileで互換確認する。
- Create、Mekanism、Immersive系は弾薬、車両、除染、物流の需要へ接続する。
- レシピロックで進行を止めず、専門家には効率、追加生産、品質、割引を与える。

### 6.7 移動と物流

- 徒歩、車、バイク、飛行機、船、鉄道を距離と物資量で使い分ける。
- Convoyは拠点間を移動し、輸送、補給、襲撃、救援という目的を持つ。
- 鉄道は単なる景観ではなく、友好都市、工業拠点、港、前線を結ぶ物流網にする。

## 7. ストーリー

### 7.1 世界の核

感染災害後、旧政府の隔離計画「PROJECT DEADZONE」は停止していない。AEGIS、Remnant、WARDENなど複数の組織と自律システムへ分裂したまま、矛盾した命令を実行し続けている。

物語の問いは次の三つである。

- 人類を守るために、どこまで自由を制限してよいか。
- 感染へ適応した存在を、人類として扱えるか。
- 壊れた文明を復旧するのか、別の社会を作るのか。

## 8. ワールド生成

### 8.1 ワールド生成の役割

ワールド生成は「街を作る技術」ではなく、コアループを空間へ配置する仕組みである。

都市の完成判定は俯瞰の美しさではない。次の行動が自然につながるかで判断する。

- 友好拠点で準備できる。
- 道路・鉄道・水路で目的地へ向かえる。
- 途中に小規模探索、救難、交易、危険がある。
- 都市内に役割の異なる地区と施設がある。
- 地上、屋上、地下を使って侵入・戦闘・撤退できる。
- 勢力、住民、Named、Loot、Quest、BGMが場所へ結び付く。
- 制圧後に地域の状態が変わる。

### 8.2 Lost Citiesとの関係

Lost Citiesは有力な生成Backendの一つだが、PROJECT DEADZONEそのものではない。

- 既存の建物、都市密度、荒廃表現、地下設備は再利用する。
- 地形へ追従しないグリッド、海上の床抜け、道路と鉄道の衝突はそのまま採用しない。
- バニラJigsaw、独自Datapack、既存Structure MOD、外部都市データ、Asset配置を組み合わせる。
- Lost Citiesで実現しにくい都市間道路、集落、港、鉄道は別系統で接続する。

### 8.2.1 規模ごとの生成責任

- 大都市・中規模都市: 現在開発中のPDZ City Generatorが都市構造を担当し、Lost Cities等のAssetを利用する。
- 小都市・町・集落: Village/Jigsaw方式で道路、入口、建物、広場、産業施設を一体生成する。
- 勢力基地: 既存Structureを拠点化し、Faction、Core、Spawner、Trader、Namedを注入する。
- 初期友好都市: 現キャンプの役割を拡張した半固定Starter Townとして生成する。

詳細は `PROJECT_DEADZONE_Urban_Settlement_Trade_Job_Framework_v0.1.md` を正本とする。

### 8.3 都市生成パイプライン

1. 地形、水辺、谷、既存Structure、地域Tierを解析する。
2. 都市中心、駅、港、工業核、行政核などのAnchorを決める。
3. 都市間幹線、都市内幹線、地区道路、生活道路の順で道路網を作る。
4. 文化圏、気候、人口、産業、立地から都市類型を選ぶ。
5. 商業、住宅、工業、医療、行政、交通、緑地へ地区を分ける。
6. 道路幅、接道、入口、地盤、高さ、隣接用途に合う建物Assetを配置する。
7. 駅前、幹線終端、港、交差点へ重要施設とLandmarkを置く。
8. 駐車、街路樹、電柱、標識、路地、裏庭、瓦礫など生活スケールを加える。
9. 荒廃度、勢力、住民、Spawner、Core、Loot、Trader、Questを注入する。
10. 地面欠落、入口段差、道路切断、線路衝突、空中Spawnを自動検査する。

### 8.4 都市類型

現在の基本系統は次の8種とする。

- 五大湖グリッド都市圏
- 北太平洋・雨都市圏
- 寒冷・冬季地下都市圏
- 乾燥・砂漠スプロール都市圏
- 湿地・デルタ都市圏
- 熱帯沿岸・観光都市圏
- 山岳・高原回廊都市圏
- 地中海・乾燥海岸都市圏

各系統で大・中・小、住宅・商業・工業・観光・港湾などの機能、崩壊状態を抽選する。同じ建物セットを全バイオームへ置かない。

### 8.5 「生きた都市」へ必要なもの

Millénaireの思想を次の形で取り入れる。

- 都市・集落に文化、名称、得意産業、人口、需要を持たせる。
- 住民が食料、医療、燃料、部品を生産・消費するように見せる。
- 友好、中立、敵対、占領、避難、感染という状態を持たせる。
- 都市間に交易路、鉄道、Convoy、救難信号を持たせる。
- プレイヤーの行動で守備、商品、人口、BGM、外観が変わる。

MCA、Recruits、Trader/NPC、勢力システムは住民層として利用し、1つのMODへ全責任を押し付けない。

### 8.6 現在の都市生成R&D

- Arnis由来の現実都市データと複数の配布Worldを解析中。
- 外部Assetを建物単位へ切り出し、3D Building Editorで確認・修正・保存する方式へ移行済み。
- レビューQueueは78件。No.1～16は初回目視で大きな破綻なし。
- 78件すべてが採用済みという意味ではない。用途、入口、分割、Palette、品質を個別に判定する。
- 都市Generatorへ直接流す前に、Building GeneratorとAsset Libraryを独立して完成させる。
- 現段階の都市生成は研究試作であり、現行マルチの正式Worldgenを置き換える品質には未到達。

### 8.7 都市生成へ使う開発時間の制御

都市生成は独立R&Dとして進めるが、次の縦切りが成立するまでプロジェクト全体を止めない。

**友好都市1つ + 敵対地区1つ + 中立集落1つ + Convoy経路1本 + 地下施設群1つ**

この縦切りで準備、遠征、戦闘、生活、交易、帰還、世界変化が回ることを確認してから都市系統を増やす。

### 8.8 初期友好都市

初期友好都市はMMOのStarter Townとして、到着、Career、生活、市場、工房、交通、行政の各区画を持つ。Lobby/PrologueでClassを確定後、都市内のCareer OfficerとJOB Mentorを訪ねて就職し、訓練、補給、最初の納品を経て遠征へ出る。Class/JOB選択中に転送せず、確定操作後だけ移動する。

## 10. 開発判断ルール

新しいMOD、機能、建物は次の順で判定する。

1. コアループのどこを改善するか説明できるか。
2. 既存システムと責任が重複しないか。
3. マルチで同期、負荷、友敵、進行が破綻しないか。
4. プレイヤーへ効果、条件、危険が日本語で見えるか。
5. T0～T3のどこで使うか決まっているか。
6. 一度使って終わらず、再訪・Build・経済へ接続できるか。

「面白そうだが置き場所が未定」のMODは即導入せず、検討一覧へ置く。
